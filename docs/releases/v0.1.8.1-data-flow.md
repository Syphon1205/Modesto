# Modesto 0.1.8.1 — Pre-change data flow notes

Inspected before implementing the Provider Tools + Teams redesign. Existing user data (rooms/chats/projects/provider config/credentials) must be preserved.

## Provider path (settings → picker)

1. **Settings (manual picker)** — Client `AppSettings.hiddenProviders` / `providerOrder` in `apps/web/src/appSettings.ts` drive Settings → Providers → “Visible providers” DnD (`_chat.settings.tsx`). Hide/show dual-writes `ServerSettings.providers.*.enabled`.
2. **Detection** — `ProviderHealth` (`apps/server/src/provider/Layers/ProviderHealth.ts`) probes enabled providers via `providerRuntimeDiscovery` + CLI/auth checks; caches under `{stateDir}/provider-status/`.
3. **Install/update** — `server.updateProvider({ action: "install" | "update" })`. npm install for a subset (codex/claude/gemini/opencode/pi); poolside via install script; others often “no safe in-app install”. Progress in `ServerProviderStatus.updateState`.
4. **Validation / auth** — Status shape: `status` ready|warning|error, `available`, `authStatus`, optional `versionAdvisory` / `updateState`. Send gate: `available && authStatus !== "unauthenticated"` (`providerAvailability.ts`).
5. **Launch** — Orchestration → `ProviderService` → adapter registry → provider adapter (`startSession` / `sendTurn`) with `ProviderStartOptions` binary paths.
6. **Composer picker** — Static `PROVIDER_OPTIONS` filtered by `hiddenProviders`, sorted by `providerOrder`, then live-disabled from `ServerProviderStatus`.

**Kinds today:** codex, claudeAgent, cursor, poolside, gemini, grok, droid, kilo, opencode, pi. Hugging Face / Qwen / Kimi appear only as model labels / OpenCode upstream IDs, not as `ProviderKind`.

**Gaps vs 0.1.8.1 goals:** manual hide/order owns picker membership; status taxonomy too coarse; no repair/remove/unified install stages; HF/Qwen/Kimi not first-class.

## Teams path

1. **No Room entity** — `/teams` projects `store.projects` + `store.threads` via `apps/web/src/lib/teamsSpace.ts`. “Project space” ≡ project; “run” ≡ thread.
2. **Layout** — App nav sidebar + Teams card with fixed 3 columns (spaces list | main `max-w-5xl` | participants). Selected project / timeline filter are local `useState` (not persisted).
3. **Contents** — Runs (cap 8, non-archived), timeline (activity kind substring filters), participants (You + unique providers). Objective lives on `ThreadHandoff`, not room-level.
4. **Cowork overlay** — `coworkThreadStore` localStorage marks; Teams sidebar filters to `kind==="teams"` but “New room run” does not mark cowork → orphaned filter.
5. **Archive** — Thread `archivedAt` via shared migrations; no room archive UI on Teams.

**Gaps:** crowded panels; every project treated as a space; no searchable/archivable rooms; no collapsible context drawer; weak empty onboarding; center width capped.

## Preservation rules

- Do not delete SQLite projections, credentials, or client settings keys that older clients may still read.
- Prefer additive schema fields and deprecating UI for `hiddenProviders` / `providerOrder` rather than hard-removing persisted keys.
- Room semantics must project over existing projects/threads (additive metadata only if needed).
